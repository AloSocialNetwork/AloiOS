# Сверка механики чата с Telegram iOS

Референс: официальный Telegram iOS, коммит
`6ad963e5b62d354da79040f388ae2b9132fb17b8`.
Проверка по Apple Design, правилам локального feedback, доступности и
производительности SwiftUI. Это конкретный проход по перечисленным ниже
компонентам, а не утверждение о полном равенстве двух мессенджеров.

## Исходники, которые сверялись

- [Стекло и нажатия](https://github.com/TelegramMessenger/Telegram-iOS/blob/6ad963e5b62d354da79040f388ae2b9132fb17b8/submodules/TelegramUI/Components/GlassBackgroundComponent/Sources/TouchEffect.swift), `GlassBackgroundComponent.swift`, `LegacyGlassView.swift`.
- `ChatTextInputPanelNode/Sources/ChatTextInputPanelNode.swift`.
- [Миниатюра](https://github.com/TelegramMessenger/Telegram-iOS/blob/6ad963e5b62d354da79040f388ae2b9132fb17b8/submodules/TelegramUI/Sources/OverlayMediaControllerNode.swift), `UniversalVideoGalleryItem.swift`.
- [Дата](https://github.com/TelegramMessenger/Telegram-iOS/blob/6ad963e5b62d354da79040f388ae2b9132fb17b8/submodules/TelegramUI/Components/Chat/ChatMessageItemImpl/Sources/ChatMessageDateHeader.swift).
- Компоненты `ChatMessageBubbleItemNode`, `ChatMessageDateAndStatusNode`,
  `ChatMessageFileBubbleContentNode`, `ChatMessageInstantVideoBubbleContentNode`,
  `ChatMessageInteractiveMediaNode`; `ContextUI/ContextController.swift`,
  `Display/Source/ContextGesture.swift`.
- `ChatMessageItemCommon`: компактный кружок 212 pt, расширенный не больше
  404 pt; `ChatMessageReplyInfoNode`: обычный ответ — имя и текст в одну
  строку каждый, 14 pt semibold/regular.
- `ReplyAccessoryPanelNode`, `ForwardAccessoryPanelNode`: высота 45 pt,
  крестик 44 pt, ограниченная вертикальная линия 2×35 pt.
- `ChatTextInputMediaRecordingButton` и
  `LegacyComponents/TGModernConversationInputMicButton.m`: удержание 0.19 s,
  отмена во время движения после 150 pt, фиксация после 110 pt; при отпускании
  отдельные пороги 100/60 pt и скорость 400 pt/s.
- `CallScreen/PrivateCallScreen`, `ButtonGroupView`: активная кнопка 56 pt,
  аватар 136 pt, имя 28 pt. Это сверка представления, не перенос транспорта звонков.

## Найденные расхождения и изменения Alo

| Компонент | Ошибка/расхождение | Изменение |
| --- | --- | --- |
| Возврат | Разрешалось закрытие вправо и влево | Только положительное горизонтальное движение; вертикальное намерение отклоняется до захвата жеста |
| Конкурирующие жесты | Все recognizer могли работать одновременно | Совместное распознавание только со скроллом; composer, scrubber и миниатюра владеют своими касаниями |
| Прокрутка истории | SwiftUI long-press на всей строке и drag-телеметрия конкурировали со ScrollView | Контекстное нажатие — нативный recognizer, движение scrubber — пассивный наблюдатель; прокрутка не получает ещё один SwiftUI pan |
| Меню текста/подписи | Обработчик фото/реакции мог подавить удержание соседнего текста; область охватывала пустой alignment slot | Приоритет стационарного удержания над child tap, без захвата настоящих scroll/back pans; recognizer ограничен видимым пузырём |
| Глубина навигации | Список почти не двигался под чатом | Параллакс списка 30% от смещения; тень с правильной стороны |
| Видеослой | Два представления одного AVPlayer, перенос через `Task.yield()` | Один реальный `UIView/AVPlayerLayer`, атомарно переподключаемый к host; старый host не может очистить новый |
| Перетаскивание миниатюры | Координаты движущейся SwiftUI view и повторное зажимание позиции | Стационарная система координат UIKit, движение 1:1 без пересчёта дерева истории |
| Магнитные края | Сохранение произвольной высоты и потеря скорости | Четыре безопасных угла, прогноз по скорости, пружина 0.3 s; прерывание из presentation position, сохранение выбранного угла |
| Миниатюра/кнопки | Полноэкранный прозрачный host мог забирать касания | Точное круглое hit-testing, запрет hit-testing для inline-состояния; верхние панели выше миниатюры |
| Закрытие | Непрозрачное поведение верхнего крестика | Одна команда stop очищает item, player, layer и observers; крестик только в верхнем плеере, swipe-dismiss у миниатюры |
| Пауза в плеере | Промежуток между двумя штрихами иконки не входил в область касания | Полный прямоугольник 44×44 для паузы, скорости и закрытия, семантические accessibility labels |
| Стекло | Слишком светлый материал и два эффекта растяжения | Тёмная tint; iOS 18 — публичный тёмный UIKit material; один локальный touch effect |
| Нажатие | Один фиксированный scale независимо от формы | Lift зависит от размера, растяжение от движения пальца; отдельные параметры подъёма и отпускания |
| Дата | Фиксированная координата/расчётная высота плашек | Фактическая измеренная высота chrome, дата под плеером; 22 pt, 13 pt medium, 6 pt горизонтальные поля |
| Разделители даты | Live blur у каждого разделителя истории | Один live blur у закреплённой даты, простые полупрозрачные фоны у движущихся дат |
| Галерея | Создание AVPlayer у соседних видеостраниц | Плеер только у активной страницы; освобождение после переключения/закрытия |
| Метаданные | Один недоступный asset мог держать очередь проб | Deadline 3 s с отменой AVFoundation; короткое отрицательное кэширование |
| Доступность | Декоративный UIKit blur попадал в дерево контролов | Материал исключён из accessibility; семантика остаётся на настоящем контроле |
| Материал и hit-testing | Glass-host охватывал семантический контрол/стек, а не только фон | Стекло — декоративный фон без hit-testing; нажатие остаётся на настоящей кнопке |
| Тесты | Deployment target приложения 18.6, тестов 17.0 | Цели тестов выровнены с приложением; офлайн-тесты не наследуют Debug UI fixture |
| Нижнее меню | Исчезало при открытии чата, заново вставлялось после возврата | Постоянно смонтировано под слоем чата, без анимации повторного появления |
| Завершение свайпа | Один пружинный settle независимо от скорости | Нативная translation без стартового скачка, remaining distance / release speed с ограничением 50–200 ms; отмена 100 ms |
| Ответ в composer | Неограниченный Shape/длинное имя могли растягивать панель | Единая плашка reply/edit/forward 45 pt с обрезкой строк и крестиком 44 pt |
| Цитата в сообщении | Длинный автор без lineLimit; неизвестное имя и имя файла вместо понятного типа медиа | Две ограниченные строки, 14 pt, лёгкий фон и линия 2 pt; имя берётся из данных собеседника; переход к исходному сообщению |
| Кружок | Разные 184/196 pt в обычном/составном сообщении | Компактный диаметр 212 pt в обоих случаях, ограниченный шириной экрана |
| Composer | Видимая плашка совпадала с увеличенной областью касания | Видимый размер 40 pt, область касания минимум 44 pt; многострочный ввод может расти |
| Запись | Фиксация уже на 80 pt, без отдельной оценки отпускания | Пороги и release velocity сверены с Telegram, декоративный круг 110 pt, отдельные вход/выход, lock выше кнопки |
| Выбранное видео | Предпросмотр читал пустой Data у зашифрованного файла; full-size синхронный кадр в detached-task | File-backed secure playback URL, общий сериализованный cache, кадр не более 320 px, deadline 3 s, отмена обновления view после ухода |

## Что нельзя объявлять исправленным без дополнительного измерения

- Полный переход на Telegram-подобный виртуализированный `ListView` отсутствует:
  история Alo пока использует `LazyVStack` и измерения видимых строк.
- Голосовые пока имеют отдельное владение проигрыванием в строках. Для
  непрерывной очереди при выгрузке строки нужен общий audio playlist coordinator,
  а не новая анимация кнопки.
- Навигационный settle в Alo остаётся SwiftUI-переходом. Его текущая
  presentation position теперь измеряется для перехвата нового жеста;
  перетаскивание миниатюры реализовано отдельно на UIKit. Это не означает,
  что все переходы приложения обладают той же механикой.
- Просмотр фото пока не имеет полного набора Telegram-жестов zoom/dismiss и
  shared-element-перехода из сообщения. Стандартный AVKit-плеер не является
  копией Telegram gallery player.
- Реакции отделены от расчёта ширины сообщения. Проверены шаг рядов 36–40 pt,
  области касания не меньше 44 pt и отступ времени 10 pt. Это не заменяет
  просмотр всех сочетаний длинного имени, вложений и большого Dynamic Type.
- Верхняя плашка голосового пока не перематывает историю к активному
  сообщению по нажатию на заголовок. Полная логика playlist/navigation Telegram
  требует отдельной реализации и проверки.
- Связь, реальная отправка, камера и GPU/FPS на физическом iPhone не
  подтверждаются офлайн-фикстурами и успешной компиляцией.
- iOS 18 проверяется fallback-режимом на доступном симуляторе 26.2; это
  не заменяет проверку на реальном iOS 18.
- Предпросмотр выбранного видео приведён к общему cache, но фриз при
  настоящей отправке кружка нельзя объявлять устранённым без замера
  шифрования, upload и сервера на физическом устройстве.
- Порог завершения возврата в Alo намеренно оставляет защиту от движения
  менее 24 pt и обратной скорости; правый край учитывает доступный пальцу
  путь. Остальная механика сверяется с Telegram, но это не буквальная копия
  его NavigationController.
- `LegacyGlassView` Telegram использует частные backdrop/filter API.
  Alo их не включает: iOS 18 fallback основан на публичном UIKit material,
  статическом световом крае и тени. Буквальное совпадение преломления не заявляется.
- Полная геометрия звонков, экран выбора камеры и интерактивные переходы
  между remote/local video ещё требуют отдельного прохода; размеры кнопок
  и успешный fixture-тест не доказывают исправность настоящего звонка.

## Проверка

- После фиксации нижней панели и навигационного settle: **19 тестов /
  23 запуска с параметрами, без ошибок** на большом iPhone 17 Pro.
  `/private/tmp/alo-chat-20261001-navigation-reply2.xcresult`.
- После правки цитаты и размеров: **27 тестов / 33 запуска, без ошибок**
  на большом iPhone 17 Pro. Проверены длинный автор, переход к оригиналу,
  отмена reply, legacy glass, удержание нижней панели и полный цикл кружка.
  Скриншоты просмотрены; результат:
  `/private/tmp/alo-chat-20261001-reply-sizes.xcresult`.

- На большом iPhone 17 Pro, iOS 26.2, повторно прошли: возврат во время
  воспроизведения, прокрутка при активном кружке, расширение/миниатюра/возврат,
  перетаскивание и верхний крестик, swipe-dismiss миниатюры, пауза/скорость/
  закрытие голосового. Результат: `/private/tmp/alo-chat-20261001-final2.xcresult`.
  Два оставшихся сбоя контекстного жеста не были сочтены успешными тестами.
- После исправления приоритета удержания прошёл тест edge-to-edge медиа и
  полей контекстного меню: `/private/tmp/alo-chat-20261001-context-final.xcresult`.
  Там же прокрутка и возврат не регрессировали. Проверка реакции наткнулась
  на точность AX (`43.99999999999994` вместо `44`); добавлен допуск 0.01 pt,
  а не уменьшена кнопка.
- На компактном экране 375 pt, iPhone SE (3rd generation), iOS 26.2:
  **31 тест / 37 запусков с параметрами, без ошибок**. 26 unit-тестов
  владения плеером, геометрии, доступности и офлайн-медиа; 5 UI-тестов
  возврата из центра/справа, запрета закрытия справа налево, legacy glass,
  изменения реакций на пяти типах сообщений и swipe-dismiss миниатюры.
  Результат: `/private/tmp/alo-chat-20261001-small.xcresult`.
- После сужения контекстного жеста до видимого пузыря: ещё **7 UI-тестов
  без ошибок** на 375 pt. Подпись фото, повторные реакции, удержание в пустом
  месте, back/scroll во время воспроизведения, полный цикл кружка и режим
  Reduce Motion / Reduce Transparency. Результат:
  `/private/tmp/alo-chat-20261001-small-final.xcresult`.
- В fixture смешанной истории на большом симуляторе память составляла
  примерно 86–88 MB в трёх проходах. Это не FPS, не замер физического
  телефона и не доказательство улучшения относительно отсутствующего baseline.
- Уточнение проверки 1 октября, 20:31 МСК: сервер слушал `*:3000`,
  `127.0.0.1:3000/health/live` отвечал `ok: true`. LAN-адрес `192.168.0.26`
  совпадал с конфигурацией, но прямой запрос к нему не проходил даже без
  HTTP-прокси. Доступ с телефона, авторизация и настоящая отправка не
  подтверждены. Настройки VPN/firewall и данные аккаунта не изменялись.

- Debug-сборка для подключённого физического iPhone 16 Pro успешно завершена
  с подписью проекта. Результат:
  `/private/tmp/alo-chat-20261001-device-build.xcresult`. Предупреждения
  AVFoundation и ориентации iPad остаются; успешная сборка не означает
  отсутствие этих технических долгов.
