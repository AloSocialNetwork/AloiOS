# V38 — производительность чатов и локальный запуск

25 сентября 2026. Дизайн отложен по просьбе пользователя; работа касается ресурсов, прокрутки, возврата в список, метаданных аудио и запуска без сети.

## Исправления

- Кружки в истории больше не создают `AVPlayer` при появлении. Используется постер до 320 px; очередь извлечения кадров/длительности последовательная, запросы объединяются, кэш ограничен 12 MiB и 64 записями. Постер освобождается из состояния исчезнувшей строки. Истёкшие/удалённые защищённые вложения не выдаются из кэша.
- Одновременно играет одно голосовое или кружок. При запуске другого прежний плеер освобождается. При обновлении прогресса `AVPlayerLayer.player` не переназначается заново.
- Аудиограмма считается в фоне блоками по 4096 кадров вместо полного PCM-буфера всей записи на главном потоке. Голосовые черновики теперь, как кружки, хранятся в зашифрованных файлах, без inline base64-копии. Предпрослушивание работает с защищённым файловым URL.
- Обновления уровня микрофона наблюдаются только элементами записи, не всем `ConversationView`. Во время подготовки записи есть неблокирующий индикатор.
- Длительность новых записей берётся из рекордера/экспортированного медиа, сохраняется в зашифрованных метаданных и outbox. Для старых сообщений определяется до Play отдельным asset-запросом без плеера. Ошибка загрузки не подменяется выдуманным временем.
- Геометрия прокрутки и задачи скрытия даты больше не публикуются в SwiftUI-состояние на каждом кадре. ISO-даты кэшируются как моменты времени, а не отформатированные строки. Видимые сообщения, разделители дат, поиск ответа по ID и проекция опросов рассчитываются один раз на проход списка, не для каждой строки заново.
- Зоны перемотки проверяются в момент начала касания, без постоянной передачи координат всех контролов через весь чат. Движение влево закрывает чат по уточнению пользователя; привычное вправо сохранено. Центр кружка допускает возврат, его кольцо остаётся перемоткой. Вертикальные движения, короткие рывки и разворот жеста защищены.
- Сохранённый аккаунт открывается до первого сетевого запроса. Первый вход без кэша сразу показывает вход, не долгую заглушку. Обновление идёт в фоне, при ошибке есть статус и повтор с паузами 3–30 секунд. При уходе в фон/смене аккаунта ожидания отменяются.
- Debug IP физического iPhone обновлён на текущий адрес Mac `192.168.0.26`. Симулятор сохраняет `127.0.0.1`, Release — HTTPS. Инструкция: `LOCAL-SERVER-RU.md`.

## Измерение прокрутки

Одинаковый XCTest-сценарий `testMixedMediaScrollPerformance`: 60 строк, чередование кружков и аудио, два локально сгенерированных коротких файла, 3 повтора пары вертикальных жестов. iPhone 17 Pro Max, iOS 26.2 Simulator, Debug. Это не измерение FPS физического устройства и не сетевой upload-бенчмарк.

Первый замер уже включал ленивые плееры. Сравнение ниже показывает **дополнительный эффект исправлений пересчёта списка и геометрии**:

| Метрика | До исправления пересчётов | После |
| --- | ---: | ---: |
| CPU time, среднее за сценарий | 5,143 s | 0,592 s |
| CPU time, три повтора | 5,058 / 5,283 / 5,087 s | 0,981 / 0,381 / 0,414 s |
| Peak physical memory, среднее | 108,44 MB | 106,86 MB |
| Время XCTest-сценария с ожиданиями | 5,686 s | 2,381 s |

У последнего CPU-замера высокая вариативность первого/последующих проходов (46,5%). Не выдавать это за гарантию ускорения приложения в 8,7 раза. В отдельном sampling-прогоне до исправления SwiftUI занимал основную часть главного потока; повторялись `visibleConversationItems`, разбор дат и обработка геометрии. Этот диагностический прогон был остановлен после зависания ожидания idle в XCTest; его цифры не включены в таблицу.

## Проверки

- Большой экран: 21 unit-тест + 10 UI-тестов — пройдены. Включены открытие из кэша при недоступном сервере, первый запуск без кэша, метаданные/защищённые файлы, повторное сохранение outbox, возврат из центра и в обе стороны, перемотка, меню, остановка и предпрослушивание записи.
- Маленький экран (375 pt, iPhone SE, iOS 26.2): 16 unit-тестов + 5 UI-тестов — пройдены. Проверены возврат из центра и с правой стороны в обе стороны, приоритет перемотки, длительность до запуска воспроизведения, остановка и предпрослушивание голосового без отправки.
- После исправления захвата `self` при возврате результата фоновой обработки: повторная сборка, 5 unit-тестов медиа/офлайн-запуска и UI-тест записи → остановки → предпрослушивания прошли. Предупреждение Swift о захваченном `self` устранено.
- `git diff --check` проходит. База, аккаунты и работающий сервер не сбрасывались; PR/commit/deploy не делались.

## Что пока не доказано

Запись камерой и отправка длинного кружка на физическом iPhone ещё не профилировались. Полное отсутствие всех вылетов не подтверждено: доступные локальные crash-отчёты были от старого симулятора, а не от телефона пользователя. Нужен повтор сценария пользователя на новой сборке, при повторном вылете — соответствующий свежий crash log.

Сервер отвечает HTTP 200 на `127.0.0.1:3000/health/live`. LAN-проверка из среды агента возвращает системную ошибку подключения. Доступ с iPhone и ограничения Wi-Fi колледжа пока не проверены; инструкция содержит отдельную проверку Safari на телефоне. Не отключать защиту системы и не открывать сервер в интернет ради локального теста.
