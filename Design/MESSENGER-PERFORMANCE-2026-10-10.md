# Мессенджер: оптимизация истории и непрерывность кружка

Нативный iOS-клиент Alo, SwiftUI/UIKit, минимальная версия iOS 18.6.
Это ограниченный проход по истории сообщений, предпросмотрам и миниатюре,
а не заявление о завершении всей соцсети или точной копии Telegram.

## Референс и правила

Прочитаны Apple Design, Write Swift, Animate, Review Animations и UI/UX Pro Max.
У `apple-design-dickwu` отсутствуют `references/hig/`; подробный HIG-аудит
не заявляется. Второй Apple Design применён к непрерывности жеста,
перехвату с текущей позиции и Reduced Motion. UI/UX Pro Max использован
для конфликтов жестов и областей нажатия. Write Swift — для отмены задач,
ограничения конкурентности и тестирования состояния, а не для смены всей
архитектуры приложения.

Локальный checkout официального Telegram iOS: `6e370e06d147b091b07903071cb1b8a22152492d`.

- [InteractiveTransitionGestureRecognizer](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/Display/Source/InteractiveTransitionGestureRecognizer.swift): ось жеста, пороги 2/10 pt и исключения для горизонтальных контролов.
- [NavigationContainer](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/Display/Source/Navigation/NavigationContainer.swift): интерактивный переход по native translation.
- [OverlayMediaControllerNode](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/TelegramUI/Sources/OverlayMediaControllerNode.swift): движение миниатюры за пальцем, docking, скорость отпускания, резерв 48 pt над нижними контролами.
- [OverlayInstantVideoNode](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/TelegramUI/Sources/OverlayInstantVideoNode.swift): владение общей видеоповерхностью и отдельный overlay host.

Референсы изучены, исходники/ассеты Telegram не скопированы. Alo сохраняет
свои публичные UIKit/AVFoundation компоненты и отдельную защиту от
случайного закрытия чата. Транспорт и архитектура Telegram не заменяют
наш сервер. Размеры и все функции Telegram этим проходом не уравниваются.

## Что исправлено

### История

`AloChatHistoryProjectionCache` хранится внутри конкретного ConversationView.
Один неизменяемый снимок содержит видимые сообщения, индексы, даты и
состояния опросов. Повторный render не разбирает JSON событий опроса и не
форматирует даты всей переписки заново. При поиске опросы вычисляются
один раз, а не для каждого проверяемого сообщения.

Ключ включает полное содержимое сообщений, канонические опросы, пользователя,
выбранную тему, поисковый запрос, текущие сутки, часовой пояс и locale.
Изменения текста, реакций и закрытие опроса не скрываются за проверкой
только ID/количества. Кэш не глобальный и не смешивает аккаунты.

### Предпросмотры

Вместо цепочки `Task`, ожидающих друг друга, используется очередь с
продолжениями ожидающих потребителей. Обычный режим — один probe.
Отмена последнего потребителя удаляет ожидающий запрос либо отменяет
AVFoundation и освобождает активный слот. Другая строка, ожидающая тот же
URL, сохраняет свой запрос. Отмена вызывающего task больше не ждёт
ответа старого asset.

Очистка кэша немедленно возвращает пустой результат всем ожидающим.
Поздний ответ проверяет UUID операции: он не может оживить очищенный
кэш или завершить новый запрос для того же URL. Реальная отмена
AVFoundation кооперативная; между отменой старого probe и освобождением
его системных ресурсов возможен короткий overlap, не бесконечная
очередь полных decrypt/decoder операций.

Проверка duration и генерация изображения имеют отдельные deadline
по 3 секунды. После недоступного/невалидного finite message asset
генерация изображения не запускается. Это устраняет ситуацию, когда
image request начинался после уже сработавшего единственного timeout.
Постеры ограничены 320 px / 12 MiB, на диск в открытом виде не пишутся.

### Кружок

Плавающий UIKit-container остаётся смонтированным при переносе inline ↔
floating и stop/play. Прозрачный полноэкранный host не перехватывает
касания вне реального круга. Движение остаётся 1:1, settle можно прервать
с текущей presentation position. Используются один AVPlayer и одна
видеоповерхность; скрытый host не забирает видео у видимого.

Прогресс inline вынесен в отдельный маленький View. Его tick не обновляет
borrowed video host. В миниатюре кольцо интерполируется через
CAShapeLayer.strokeEnd, а не таймером, публикующим каждый animation frame
на всё дерево чата. Интерполяция линейная 150 ms; seek/reset не запускают
большой оборот миниатюры. Reduced Motion отключает интерполяцию.
Добавлен Reduced Motion для уже существовавшей анимации изменения списка.

Визуальная проверка обнаружила перекрытие стрелки «вниз» кружком,
прикреплённым к правому нижнему углу. Добавлен постоянный резерв 48 pt,
как в `OverlayMediaControllerNode.nodePosition`, над composer/input inset.
Он не меняется при каждом появлении стрелки, поэтому не вызывает скачок
докинга во время скролла. UI-регрессия проверяет непересечение и доступность
стрелки после переносов миниатюры.

### Переход к последним сообщениям

Расширенная UI-проверка нашла реальный сбой: с открытой клавиатурой
`ScrollPosition.scrollTo(edge: .bottom)` доходил до оценочной высоты
LazyVStack, но последние два новых сообщения оставались ниже видимой
области. Кнопка теперь использует конкретный нижний ID через
ScrollViewProxy на следующем main turn после переключения keyboard-follow.
Нижний якорь стоит после сообщений и composer inset. Проверка требует,
чтобы последнее новое сообщение было над composer, стрелка исчезла,
а черновик сохранился; assertion не ослаблен и timeout не увеличен.

## Проверка

Финальный unit/performance + UI прогон на iPhone 17 Pro / iOS 26.2:
53 логических теста / 63 запуска с параметрами, 0 failures. Включает отмену очереди,
равные копии истории, обновление реакций/опросов без смены ID, даты разных
дней, владение единственным player, свайп во время воспроизведения,
три цикла inline ↔ miniature, свободную стрелку «вниз», удаление кружка
свайпом, переход к новым сообщениям с клавиатурой и Reduced Motion.

CPU-бенчмарк: 1000 сообщений с разными timestamp, 100 сообщений-опросов,
пять измерений на симуляторе iPhone 17 Pro. Повторный render измеряется
пачками по 30 проходов; холодный снимок — по одному.

| Участок | Среднее время одного прохода |
| --- | ---: |
| Старый повторный разбор истории | 14.05 ms |
| Сохранённый снимок, та же array storage | 0.0035 ms |
| Сохранённый снимок, равная копия в другой storage | 0.335 ms |
| Первый холодный снимок | 16.15 ms |

Это НЕ FPS, не ускорение всего приложения и не обещание устранения всех
фризов. Холодный снимок пока рассчитывается синхронно на MainActor;
большие истории требуют отдельного измерения/асинхронной подготовки.
«Холодный» здесь означает новый projection memo; общий кэш разобранных
дат/DateFormatter в процессе уже прогрет. Это не замер старта приложения.
Для повседневных render ticks тяжёлый разбор теперь не повторяется.

## Motion review изменённого участка

| До | После | Почему |
| --- | --- | --- |
| SwiftUI удалял floating host при каждой смене владельца видео | Один host, внутренняя UIKit fade/drag | Непрерывность, меньше пересозданий и конкурирующих переходов |
| Clock invalidation охватывал inline video host | Отдельный progress-ring View | Ограничить обновление реально меняющимся индикатором |
| Видимое кольцо миниатюры менялось дискретно | Linear 150 ms от presentation value | Плавная индикация хода воспроизведения без per-frame SwiftUI updates |
| Анимация истории игнорировала Reduce Motion | Reduce Motion отключает spring списка | Движение не обязательно для чтения новых сообщений |

Оценка изменённого индикатора: направление корректное; реальные frame pacing
и ощущение жеста требуют проверки на iPhone. Это не одобрение всех
существующих анимаций приложения. UIKit/Core Animation используются
напрямую; веб-правила CSS translate не выдаются за API iOS.

## Осталось

- Реальный iPhone: Time Profiler / Animation Hitches при длинном чате,
  записи, экспорте и загрузке медиа; отдельно память с несколькими
  большими вложениями. Замеры симулятора не заменяют эту проверку.
- iOS 18 runtime: в доступных симуляторах есть только iOS 26.2.
- Голосовой player пока привязан к lifetime строки; продолжение вне
  видимого сообщения требует отдельного conversation playback controller.
- Полная проверка звонков, записи, offline/outbox, пересылок, реакций,
  модальных галерей, Dynamic Type и всех экранов соцсети — следующие
  самостоятельные проходы, а не закрытые пункты этого отчёта.
