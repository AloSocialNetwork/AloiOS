# Как запустить Alo на своём Mac и iPhone

Приложение на iPhone — клиент. Компиляция не запускает сервер: Node.js должен отдельно работать на Mac. Для теста по Wi‑Fi не нужны публикация приложения и внешний домен.

## 1. Подключить устройства

Mac и iPhone должны быть в одной сети Wi‑Fi. Mac должен оставаться включённым. При переходе в колледж адрес Mac обычно меняется — домашний IP туда переносить нельзя.

## 2. Запустить сервер

Открой приложение «Терминал» на Mac и выполни по очереди:

```sh
cd /Users/mikhail/alo
```

```sh
npm run dev
```

Оставь это окно открытым. Для остановки нажми Control+C именно в этом окне. Если написано `EADDRINUSE`, порт 3000 уже занят: возможно, сервер уже работает. Не запускай второй экземпляр и не удаляй данные.

На этом Mac зависимости уже установлены. Не нужно заново копировать `.env.example` поверх `.env`, сбрасывать базу или переустанавливать всё при каждом запуске.

В браузере **на Mac** открой `http://127.0.0.1:3000/health/live`. Должен появиться ответ с `"ok":true`. Это подтверждает, что сервер запущен, но ещё не проверяет доступ с телефона.

## 3. Узнать IP Mac

В новом окне Терминала выполни:

```sh
ipconfig getifaddr en0
```

На проверке 9 октября адрес Mac в этой сети — `192.168.0.19`. Используй результат команды сейчас, а не этот пример: при смене Wi‑Fi или точки доступа он может измениться. Если команда ничего не вывела, открой «Системные настройки → Wi‑Fi → Подробнее → TCP/IP» и посмотри IPv4-адрес. `198.18.0.1` — адрес виртуального интерфейса на этом Mac, а не его Wi‑Fi-адрес; для iPhone здесь используй адрес `en0`.

## 4. Куда вписать адрес

В Xcode открой `/Users/mikhail/AloiOS/AloiOS.xcworkspace`.

В файле `AloiOS/Networking/AloServerConfiguration.swift` найди `debugLocalDevelopmentHost`. Там две строки:

```swift
#if targetEnvironment(simulator)
static let debugLocalDevelopmentHost = "127.0.0.1" // не менять
#else
static let debugLocalDevelopmentHost = "192.168.0.19" // сюда IP Mac
#endif
```

Меняй только вторую строку. Порт `3000` добавляется автоматически. Если нужен другой порт, допустим `192.168.0.19:3001`.

В существующем `/Users/mikhail/alo/.env` также обнови **только** строку `APP_BASE_URL=http://192.168.0.19:3000`, подставив новый адрес Mac. Оставь `HOST=0.0.0.0`, `PORT=3000` и остальные настройки как есть. Перезапусти сервер через Control+C, затем снова `npm run dev`. Эта строка нужна для ссылок, которые создаёт сервер. Не заменяй весь `.env` и не публикуй его содержимое.

Выбери свой iPhone в Xcode и снова нажми Run (▶). Просто редактирование файла не меняет уже установленное приложение. Для локального HTTP используется **Debug**: Product → Scheme → Edit Scheme → Run → Build Configuration → Debug. Release требует HTTPS.

Если в Build Settings вручную заполнен `ALO_API_BASE_URL`, он имеет приоритет над этой строкой: проверь, что там не остался другой сервер.

## 5. Проверить доступ с iPhone

В Safari **на iPhone** открой, подставив свой IP:

```text
http://192.168.0.19:3000/health/live
```

Если виден `"ok":true`, сеть до сервера работает. Открой Alo. Разреши запрос доступа к локальной сети; разрешение можно проверить в «Настройки → Конфиденциальность и безопасность → Локальная сеть → Alo» ([инструкция Apple](https://support.apple.com/en-us/102229)).

Если страница не открывается, пересборка сама по себе это не исправит. Проверь:

- IP взят именно у Mac, не у телефона; в адресе есть `http://` и `:3000`.
- Mac и iPhone действительно подключены к одной сети, сервер работает.
- В существующем `.env` сервера параметры `HOST=0.0.0.0` и `PORT=3000`; после их изменения сервер нужно перезапустить. Не показывай и не отправляй весь `.env`: в нём могут быть секреты.
- macOS не блокирует входящие подключения Node.js. Не отключай целиком защиту системы: разрешается только нужное приложение.
- Для приложения, запускающего сетевую проверку на Mac, доступна локальная сеть: «Системные настройки → Конфиденциальность и безопасность → Локальная сеть» ([инструкция Apple](https://support.apple.com/en-nz/guide/mac-help/mchla4f49138/mac)).

В учебной/гостевой сети устройства **могут** быть изолированы друг от друга даже при одинаковом имени Wi‑Fi. Это возможная причина, не установленный факт о сети колледжа. Если Mac открывает сервер, а iPhone нет, проверь в своей сети или уточни у администратора, разрешены ли соединения между устройствами. Не нужно открывать сервер всему интернету или пробрасывать порт ради этой проверки.

## Если сервер выключен

После успешного входа приложение открывает ранее сохранённые данные без ожидания сервера и обновляет их в фоне. В открытом чате статус «был недавно» сменится на «Обновление…» без сдвига интерфейса; на других экранах будет компактная плашка «Нет связи · Повторить». Без предыдущего входа появится экран входа: получить аккаунт с выключенного сервера нельзя. Не загруженные раньше вложения также требуют соединения.

## Результат проверки 9 октября

Сервер перезапущен с исправлением загрузки постов и историй, слушает `0.0.0.0:3000`; `127.0.0.1:3000/health/live` вернул HTTP 200. Адрес в Debug-клиенте и `APP_BASE_URL` совпадает: `192.168.0.19`. Доступ **с iPhone пока не подтверждён**. Проверь шаг 5 на самом телефоне.

## QR-вход — проверка 10 октября

Сервер повторно перезапущен с отдельным лимитом опроса QR; адрес в этой сети остался `192.168.0.19`. Исправлен iOS-разбор кода, добавлены явное подтверждение входа и повтор после ошибки/истечения срока. Для получения изменений снова нажми Run в Xcode.

На новом устройстве выбери «QR-код» на экране входа. На устройстве с открытым аккаунтом: «Профиль → настройки → Безопасность → Подтвердить вход по QR-коду». Разреши камеру, отсканируй QR и подтверди подключение только своего устройства. Оба клиента должны обращаться к одному серверу. Код действует две минуты и одноразовый.

Это существующий сценарий внутри iOS-приложения: в веб-форму входа QR-кнопка пока не добавлена. Живое сканирование на физическом iPhone ещё нужно проверить. Подробный отчёт: `Design/QR-AUTH-2026-10-10.md`.
