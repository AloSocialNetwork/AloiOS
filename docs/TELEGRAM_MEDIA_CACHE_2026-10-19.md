# Медиа чатов: офлайн-кеш и автозагрузка

## Референс

Изучена ревизия Telegram iOS `6e370e06d147b091b07903071cb1b8a22152492d`,
а не весь репозиторий целиком. Использованы конкретные подсистемы:

- [MediaAutoDownloadSettings.swift](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/TelegramUIPreferences/Sources/MediaAutoDownloadSettings.swift):
  тип, известный размер, сеть, пресеты и исключение для небольших голосовых.
- [SyncCore_CacheStorageSettings.swift](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/TelegramCore/Sources/SyncCore/SyncCore_CacheStorageSettings.swift)
  и `Settings/CacheStorageSettings.swift`: сроки по категориям.
- [TimeBasedCleanup.swift](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/Postbox/Sources/TimeBasedCleanup.swift):
  сначала истечение срока, затем удаление давно неиспользуемого до лимита места;
  отложенная запись времени доступа.
- [MediaBox.swift](https://github.com/TelegramMessenger/Telegram-iOS/blob/6e370e06d147b091b07903071cb1b8a22152492d/submodules/Postbox/Sources/MediaBox.swift):
  разделение ссылок на ресурс и его байтов, удержание используемого ресурса.

Это адаптация правил к существующему шифрованному хранилищу Alo, не перенос
всего MediaBox/Postbox и не обещание полного совпадения с Telegram.

## Что изменено

Раньше расшифровка истории скачивала целиком каждое E2EE-вложение, включая
вложения последних сообщений в списке чатов. Теперь она регистрирует только
локальную ссылку и метаданные. Сам файл запрашивает видимая строка/плеер.
Большой или неизвестный по размеру файл требует явного нажатия.

Пресеты (MiB = 1 048 576 байт):

| Пресет | Фото | Видео / кружки | Файлы | Голосовые |
| --- | ---: | ---: | ---: | ---: |
| Мало данных | 1 MiB | Не автоматически | Не автоматически | 2 MiB |
| Средний | 1 MiB | 2,5 MiB | 1 MiB | 2 MiB |
| Высокий | 1 MiB | 10 MiB | 3 MiB | 3 MiB |
| Выключена | По нажатию | По нажатию | По нажатию | По нажатию |

Wi-Fi по умолчанию использует высокий пресет, мобильная сеть — средний.
Режим экономии данных запрещает автоматическую загрузку, но не ручное открытие.
Без сети сначала используются локальные байты. Отсутствующее медиа не выдаётся
за доступное офлайн. Переход по соседним фото в viewer не обходит автоограничения.

- Очередь файлов: максимум две передачи; одновременные запросы одного
  защищённого ресурса объединяются; ручной запрос приоритетнее ожидающего
  автоматического. Для обычных изображений дополнительно проверяется дисковый
  кеш при начале очередной передачи.
- Уход строки с экрана отменяет её спрос, но не запрос другого потребителя
  того же файла. Отменённая передача освобождает слот после фактического завершения.
- Ограничение получаемых байтов проверяется во время передачи и после неё.
  Есть резерв свободного диска для одновременно скачиваемых файлов/перешифрования.
- E2EE хранится на диске зашифрованным; старые незашифрованные голосовые/видео
  при скачивании шифруются локально. Видеоплеер читает зашифрованный файл порциями,
  а не разворачивает целый ролик в оперативную память.
- Отправленные собственные E2EE-вложения сохраняются как воспроизводимая копия
  без повторного скачивания; исходный черновик при этом не перемещается.
- Аватарки и обычные изображения используют существующий зашифрованный
  account-scoped кеш. Новая загрузка ограничена размером; обычный URLCache для
  этих запросов обходится. Лента использует этот же кеш изображений, но отдельный
  офлайн-видеокеш ленты в этой итерации не добавлен.

## Место и очистка

Настройки → «Данные и память»: объём, лимит 1/2/5/8/16 ГБ,
пресеты для двух сетей, подтверждаемая очистка скачанных копий.
Для Alo выбран конечный лимит **2 GiB по умолчанию**, по прямому требованию
ограничить расход места. В исследованной ревизии Telegram исходный общий лимит
по умолчанию неограничен — это намеренное отличие.

Срок с последнего использования: личные чаты — только общий лимит, группы —
31 день, каналы — 7 дней; инфраструктурный scope историй — 2 дня. Это не означает,
что все истории автоматически сохраняются. Обычные изображения/аватарки,
для которых нет контекста чата, относятся к preview-кешу со сроком 7 дней.
При заполнении лимита удаляются старейшие неиспользуемые копии независимо от типа.

Менеджер владеет только воспроизводимыми файлами в `AloE2EEMedia/encrypted`
(кроме `draft-*`) и `remote-image-*` в `AloOfflineSecure`. Он **не удаляет**
историю/поисковый индекс, bootstrap, ключи, черновики, outbox, исходные загрузки
и экспортированные пользователем файлы. Плеер удерживает ресурс от очистки
до освобождения asset/loader. Во время активного воспроизведения лимит может
временно превышаться; освобождение ресурса повторно запускает очистку.

Учёт — на служебной очереди, атомарный индекс без текста сообщений/ключей.
Старые файлы учитываются и после потери индекса. Данные в системном Caches
могут быть удалены iOS; кеш не является бессрочным архивом. Удалённую по квоте
копию можно скачать заново, только пока она доступна на сервере.

## Существенные отличия от Telegram

У Telegram есть несколько представлений фотографии и неполные/range-кеши видео.
Текущий сервер Alo выдаёт один зашифрованный оригинал. Поэтому неизвестный
оригинал не скачивается автоматически, а файл скачивается целиком в пределах
пресета перед воспроизведением. Предзагрузка больших видео/первых секунд из
Telegram не эмулируется скачиванием целого большого файла.

Настройка TTL по каждому чату, исключения для отдельных чатов, granular auto-download
по контактам/группам, очистка по каждому отдельному файлу, офлайн-видео ленты
и полноценный архив произвольных документов не входят в эту итерацию.

## Проверка

`AloMediaCacheTests` проверяет пороги/сети, TTL прежде квоты, LRU, активные
ресурсы, исключение черновиков/истории/внешних путей, восстановление индекса,
dedup/cancellation/concurrency и доступ к защищённым файлам после удаления
их источника. Дополнительно проверены публичный путь получения истории без
скачивания старого голосового и HTTP-загрузка через URLSession с отклонением
ответа сверх допустимого размера.

Фактический результат на симуляторе SE375 / iOS 26.2:

- 95 XCTest + 142 Swift Testing = **237 модульных проверок, все прошли**.
  Bundle: `/tmp/AloMediaCache-20261019-HTTPCheck.xcresult`.
- **1 UI-тест прошёл**, внутри два запуска: обычный текст и accessibility-размер
  с Reduce Motion. Проверены вход/возврат, подписи настроек, прокрутка до TTL;
  скриншоты просмотрены вручную.
  Bundle: `/tmp/AloMediaCache-20261019-SE-ReleaseCheck.xcresult`.
- `git diff --check` — без ошибок. На физическом iPhone и с настоящим сервером
  авиарежим/повторный запуск/длительная нагрузка в этой итерации не проверялись.

Название второго bundle — лишь имя прогона: сборка тестов использует Debug,
это не свидетельство проверки Release/App Store-сборки или физического устройства.
